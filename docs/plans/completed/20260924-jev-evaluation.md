## 状態

## 目的と確定要件

- ユーザーの要約を原文と比較する判定に TypeSafe AI の Jev を利用する。
- Jev の判定対象は「適切な要約か（はい・いいえ）」「重要情報の抽出（1〜5点）」「簡潔性（1〜5点）」「正確性（1〜5点）」「総合評価（合格・不合格）」とする。
- 評価結果に「総合得点（0〜100点）」を追加する。
- 総合得点は3つの5段階評価から等重みで算出する。
- 新しい TUI 設定画面から Groq キーと Jev キーを入力・保存する。
- 「改善点1〜3」は現行どおり Groq に原文と要約を渡して文章で生成する。
- 文章生成には引き続き Groq を使用する。

## 変更前の状態と変更範囲

- 変更前は Groq の1回の応答から8項目を解析し、表示と統計保存に使っていた。合否は解析済みの「総合評価」に従っていた。
- 変更前の TUI に設定画面はなかった。Groq キーは `GROQ_API_KEY` または利用者が手動作成する `config.toml` から読み取り、画面からの保存機能はなかった。
- `docs/SPECIFICATIONS.md` の要約評価に関する古いプロンプト反復・文字列検索の記述は、今回の評価フローに合わせて更新した。

## 動作仕様

1. `Ctrl+S` で原文とユーザーの要約を評価する。Jev には両方を名前付きの state として渡し、5つの独立した質問を1回のリクエストにまとめる。
2. 「適切な要約か」は Noul の値が0.5以上なら「はい」、未満なら「いいえ」とする。「総合評価」は合格・不合格の Choice で判定する。3つの5段階評価には、各段階を具体的に記述した Score を使う。Jev の Score は0〜4の小数値なので、四捨五入して1を加え、画面と既存統計には1〜5の整数として使う。
3. Groq は「改善点1〜3」の文章だけを生成する。現行の原文・要約比較と3項目の提示は維持し、Jev の判定を Groq の出力で上書きしない。
4. 総合得点は丸める前の3つの Jev Score（各0〜4）から `round(100 × (重要情報の抽出 + 簡潔性 + 正確性) / 12)` で算出する。最低点の組み合わせは0点、最高点の組み合わせは100点になる。画面の5段階評価は各 Score を丸めた値なので、表示点数だけから総合得点を再計算しない。合格・不合格はこの得点の閾値から決めず、Jev の「総合評価」を使う。
5. 両サービスの結果を合わせて、従来の8項目と「総合得点」を評価結果オーバーレイに表示する。合否に連動する枠線、バディ、日次・週次統計は Jev の「総合評価」を使う。
6. どちらかの API が失敗した場合は評価失敗を表示し、不完全な評価を統計に保存しない。キーやレスポンス全文をエラー表示・ログへ出さない。
7. 既存の `stats.json` を読めるようにし、新しい総合得点を保存する場合は既存レコードの欠損を許容する。過去の得点を推測して埋めない。

### Jev に渡す評価基準

- 「適切な要約か」は、原文の主旨を保ち、重要事項を伝え、要約として成立する場合を「はい」とする。
- 「重要情報の抽出」は、原文の主要事実・主張の取りこぼしを評価する。「正確性」は、書かれた内容が原文と矛盾せず、事実の追加や意味の改変がないかを評価する。「簡潔性」は、重要情報を残したうえで冗長な繰り返しや不要な詳細を省けているかを評価する。
- 各 Score の5段階は、1点を「明確な問題」、3点を「一部不足するが主旨は伝わる」、5点を「重要な欠落・冗長さ・不正確さがない」とする。2点と4点も各観点に固有の状態を記述し、数値だけを Jev に渡さない。
- 「総合評価」の合格は、原文の主旨と主要情報を保ち、重大な不正確さがなく、要約として読める場合とする。それ以外を不合格とする。5段階評価や総合得点と判断が食い違う例を含め、実データで基準を検証する。

## 設定仕様

- 起動時の Groq 認証が失敗してもメニューを開き、設定画面へ進めるようにする。メニューとトレーニング画面の `s` で設定画面を開き、保存・キャンセル後は元の画面へ戻る。トレーニング開始時に Groq キーを検証し、未設定または無効ならメニューに理由を表示して開始しない。
- 設定画面では Groq キーと Jev キーを別々に入力・保存できる。保存済みキーの実値は再表示しない。未入力で保存する場合は既存値を保持し、キャンセルは保存しない。
- Jev キーは既存の `config.toml` に別項目として保存する。Groq キーは現在どおり `GROQ_API_KEY` を設定ファイルより優先し、環境変数が有効なときは設定画面にその旨を示す。Jev キーの環境変数は今回追加しない。
- Jev キーが未設定なら評価を開始せず設定画面での入力を案内する。無効なキーや通信失敗は評価失敗として表示し、統計には保存しない。
- Unix 系の設定ファイルは保存時に所有者だけが読める権限（0600）にする。既存の設定値は保存時に保持し、書き込み失敗で既存ファイルを失わないよう一時ファイルから置き換える。保存失敗を成功扱いしない。

## 実装単位と検証

1. **キー設定**: 設定の読み書きと、選択された設定画面の入出力を実装する。既存 Groq キーの読み取り優先順位、保存済み値の保持、権限、保存失敗時の表示を検証する。
2. **判定と改善点**: Jev の5判定と Groq の改善点3件を統合する。型・範囲・欠落した応答、合否、表示順、片方の API 失敗時に統計を保存しないことを検証する。
3. **得点と永続化**: 決定した0〜100点算出方法を結果表示・保存に適用する。境界値と旧 `stats.json` の読み取りを検証する。
4. **文書と全体確認**: `docs/REQUIREMENTS.md`、`docs/SPECIFICATIONS.md`、`docs/DESIGN.md`、`docs/HELP.md`、`README.md` の該当箇所を実装と一致させ、`make check` と `make build` を実行する。実サービスでの認証・判定確認は別途実施結果を記録する。
