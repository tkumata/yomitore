# Issue #66 `jiff` に移行し、依存ツリーから `chrono` を除く

## Status

- Phase: completed
- Approval: approved
- 実機確認: ユーザ確認済み

## Goal

保守が終了した `chrono` をアプリの依存ツリーから除く。日時処理を `jiff` に移し、`chrono` に依存する `rat-text` を置き換える。既存のトレーニング履歴を引き続き利用できるようにし、集計、表示、バディ、要約入力の挙動を維持する。

## Scope

- `Cargo.toml` と `Cargo.lock` の直接依存を切り替える。
- `src/models.rs` と `src/stats.rs` の記録、保存、読み込みを移行する。
- `src/stats_analysis.rs` の日次・週次集計と評価集計を移行する。
- `src/reports.rs` のヒートマップの日付計算とバディのアニメーションを移行する。
- `src/app.rs`、`src/events.rs`、`src/ui.rs`、`src/main.rs` の要約入力で使う `rat-text` を置き換える。
- `docs/current/SPECIFICATIONS.md` の日時型、依存関係、保存形式、要約入力の記述を実装に合わせる。

## Non-goals

- ユーザによるデータ変換や設定追加を伴う移行。

## Required Behavior

以下を必須とする。

- 既存の `stats.json` を同じパスから読み込む。`timestamp`、`earned_at`、`last_training_date` は、保存されたオフセットを使って同じ時点に復元する。
- 保存時は、既存の JSON キーとローカルオフセット付きの日時形式を維持する。日時の小数秒の精度を保持し、旧版でも読み込める形式で保存する。
- `last_training_date` の省略と `null` を引き続き受け付ける。不正な日時は読み込みエラーにする。
- 日次集計、評価集計、ヒートマップの日付は、実行環境のローカルタイムゾーンで決める。ヒートマップは当日を含む直近 180 日を日曜始まりの週に配置する。
- 週次集計は夏時間の切り替えをまたぐ場合も、1 週を経過時間の 168 時間として扱う。集計区間は開始を含み、終了を除く。
- バディのペナルティは最終トレーニングから 72 時間経過した時点で適用する。バディのアニメーションは 500 ミリ秒ごとにフレームを切り替える。
- 通常モードでは `i` または `Enter` で入力モードに切り替える。`Esc` で通常モードに戻り、入力済みの要約を保持する。
- 要約欄は文字入力、改行、削除、矢印キーと `Home` / `End` でのカーソル移動に対応する。端末幅に合わせたワードラップと、カーソルに追従するスクロールを維持する。
- 入力モードで `Ctrl+S` を押すと、空白以外の文字を含む要約を改行込みで評価へ渡す。空または空白だけの要約では評価を開始しない。

## Tasks

### Task 1 日時処理と保存境界を移行する

- **Objective** — アプリが直接利用する日時型と演算を `jiff` に移す。
- **Scope** — 記録時点には `jiff::Timestamp`、暦日には `jiff::civil::Date` を使う。ローカル日付は `TimeZone::system()` で求める。週次集計とペナルティには経過時間の演算を使う。保存時は `Timestamp::display_with_offset` で現行の日時形式を維持する。
- **Acceptance Criteria** — アプリの日時処理と直接依存から `chrono` を除く。既存データの読み書きと、Required Behavior の日時処理に関する条件を満たす。
- **Verification** — 以下の項目を確認する。
  - 3 つの日時フィールドを含む旧形式の JSON で、オフセットと小数秒を含む日時の読み書きを検証する。省略、`null`、不正値も確認する。
  - ローカル日付と UTC の日付が異なる時点で日次・評価集計を確認する。
  - 夏時間をまたぐ週次境界と 72 時間のペナルティ境界を固定時刻で検証する。
  - 既存のヒートマップテストを実行する。アニメーションのフレーム選択が引き続き 500 ミリ秒単位であることを確認する。
  - `make check` と `make build` を通す。
- **Result** — `jiff 1.0.1` に移行した。旧形式の 3 つの日時フィールドを新実装で読み込み、新実装の保存値を旧実装で読み込めることを確認した。夏時間をまたぐ週次集計と 72 時間判定、ローカル日付による集計、ヒートマップのテストが成功した。アニメーションの 500 ミリ秒判定はコードで確認した。

### Task 2 要約入力を移行し、依存ツリーから `chrono` を除く

- **Objective** — 要約入力の挙動を維持しながら `rat-text` 経由の `chrono` 依存を除く。
- **Scope** — `ratatui-textarea 0.9.4` を採用候補とする。要約欄の編集状態、キー処理、描画、評価に渡す文字列の取得を移行する。
- **Acceptance Criteria** — 要約入力が Required Behavior の条件を満たす。`rat-text` と `chrono` が `Cargo.lock` に残らず、`chrono` への直接依存と間接依存が解消される。
- **Verification** — 以下の項目を確認する。
  - 現行と移行後の TUI で、複数行の日本語を入力する。幅の狭い端末で折り返し、カーソル移動、スクロールを比較する。
  - `i` と `Enter` での入力開始、`Esc` での終了と再開、`Ctrl+S` での評価開始を確認する。空白だけの要約は評価を開始せず、複数行の要約は改行を保持することを確認する。
  - `make check` と `make build` を通す。Task 1 と Task 2 の完了後、`cargo tree --locked --all-features --target all` が成功し、出力と `Cargo.lock` に `chrono` が存在しないことを確認する。
- **Result** — `ratatui-textarea 0.9.4` に移行した。52 列 × 9 行の `TestBackend` で旧版・新版の日本語の折り返し、カーソル移動、スクロール、改行を含む要約の送信操作を確認した。レビューで修正したカーソル表示、コピー、インデントも回帰テストで確認した。依存ツリーと `Cargo.lock` に `chrono` と `rat-text` がないことを確認した。`make check` は 49 件のテストを含め成功し、`make build` も成功した。
- **実機確認** — ユーザは実機確認を完了した。個別の確認項目は記録していない。
- **既知の挙動差** — 折り返し位置は単語境界の扱いによって旧版と異なる場合がある。複数行のインデントは行単位で取り消す。
